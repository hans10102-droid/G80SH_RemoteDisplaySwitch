## 1. 요약

화면 절전 중 주 모니터(Odyssey G80SH)가 약 **42초 주기로 반복 제거·재열거**되며, 유령 장치 노드가 누적되고 장치 연결/해제 알림음이 반복된다.

근본 원인은 **모니터가 스탠바이 상태에서 제품 코드가 다른 EDID를 내보내는 펌웨어 동작**이다. Windows는 제품 코드로 장치를 식별하므로, 이를 "다른 모니터가 연결됨"으로 판정하고 새 장치 노드를 생성한다.

PC 측 설정 오류는 없다. 사용자 제약(절전 유지 · 원격 사용 방식 유지 · 모니터 물리 조작 없음 · 4K240/HDR/VRR 유지) 안에서 이를 소프트웨어로 차단하는 검증된 경로는 현재 존재하지 않는다.

대상 인스턴스:
- `DISPLAY\SAM7B0C\7&16b8ddb4&0&UID256`
- `DISPLAY\Default_Monitor\7&16b8ddb4&0&UID256`

**부작용**

- 유령 모니터 노드 누적 (최대 11개까지 확인)
- 장치 연결/해제 알림음 반복
- 절전 복귀 시 해상도·창 배치 흐트러짐
- 이벤트 로그 오염 (2026-09-09 하루 1,080건)

## 6. 근본 원인 — EDID 프로파일 이중화

### 6-1. 동일 개체 확인

레지스트리에서 EDID 원본(384바이트)을 추출해 디코딩한 결과, `SAM7B0C`와 `SAM7B0B`는 **동일한 물리 모니터**다.

| 항목 | SAM7B0C | SAM7B0B |
|---|---|---|
| 모델명 | Odyssey G80SH | Odyssey G80SH |
| 시리얼 문자열 | <시리얼> | **<시리얼>** |
| 시리얼 숫자 | <시리얼 숫자> | **<시리얼 숫자>** |
| 제조 주차 | 2026년 31주 | 2026년 31주 |
| 화면 크기 | 70×40 cm | 70×40 cm |

### 6-2. 차이점 (384바이트 중 79바이트 상이)

| 오프셋 | 항목 | SAM7B0C | SAM7B0B |
|---|---|---|---|
| **10** | **제품 코드 LSB** | **0x0C** | **0x0B** |
| 24 | feature byte | 0x3B — 연속주파수(VRR) **ON** | 0x3A — **OFF** |
| 54~71 | Range 디스크립터 | flags 0x0C, 수직 **48~240Hz** | flags 0x08, 수직 30~240Hz |
| 35~36 | established timings | `21 08` | `25 CF` (레거시 모드 대량 추가) |
| 52~53 | 표준 타이밍 | 미사용 | 실제 타이밍 추가 |
| 128~255 | CTA 확장 블록 | 상세 타이밍 세트 A | 세트 B (60바이트+ 상이) |

```
SAM7B0C         = 게이밍/VRR 프로파일   (FreeSync 48~240Hz, 상세 타이밍 풍부)
SAM7B0B         = 호환/비VRR 프로파일   (VRR 없음, 레거시 모드 다수)
Default_Monitor = EDID 읽기 실패 폴백
```

과거 `SAM7B11`이라는 세 번째 변종도 3회 관측됨 (2026-09-09, 현재 레지스트리에 없음).

### 6-3. 문제의 정확한 지점

Windows는 EDID 바이트 8~11(제조자 + 제품 코드)로 장치 하드웨어 ID를 만든다.

프로파일이 전환될 때 **제품 코드까지 함께 바뀌므로**, Windows는 이를 "모니터를 뽑고 다른 모니터를 꽂은 것"과 동일하게 판정하고 새 장치 노드를 생성한다.

정상적인 모니터는 프로파일이 바뀌어도 제품 코드를 유지하고 기능 비트만 변경한다. 제품 코드를 바꾸는 것은 **펌웨어 설계 판단의 문제**다.

### 6-4. 인과 방향

```
[모니터 펌웨어] 스탠바이에서 다른 EDID 테이블 서빙
      ↓
[dxgkrnl] 바뀐 제품 코드로 새 하드웨어 ID 생성 → 새 PnP 노드
      ↓
[Windows] 이전 노드를 "누락"으로 판정 → 이벤트 1010 정리
      ↓
[반복]    42초 주기
```

GPU가 VRR 협상에 실패해서 EDID가 바뀌는 것이 아니라, **EDID가 바뀌었기 때문에** Windows가 VRR 없는 다른 모니터를 본 것이다.

### 6-5. 방아쇠 — AMD "FreeSync 색상 정확도" (2026-09-16 추가)

09-16 밤 조치 두 가지(EDID_OVERRIDE 적용, Adrenalin **FreeSync 색상 정확도 끔**)를 적용하고 재부팅했다. 그 뒤 원격+절전 28.5분 동안 churn이 0건이었다(4-4).

**EDID_OVERRIDE는 해결 요인이 아니다**
- 오버라이드는 노드 생성 이후에 적용되므로 구조상 루프를 막지 못한다 (9-1).
- 관찰 구간 내내 `SAM7B0B`가 비활성이었고 `Default_Monitor`도 없었다. 모니터가 7B0B를 내보낸 적이 없으니 오버라이드가 쓰일 기회도 없었다.

**FreeSync 색상 정확도가 방아쇠라고 보는 근거 (추정, 단독 검증 전)**
- 이 옵션은 FreeSync Premium Pro(구 FreeSync 2 HDR) 경로다. 드라이버가 모니터의 AMD 전용 데이터(색역·휘도 정보)를 읽고, AMD 전용 신호로 모니터를 FreeSync Premium Pro 모드에 넣은 뒤 GPU 쪽에서 톤매핑한다.
- 7B0C와 7B0B의 핵심 차이는 FreeSync 관련 필드(연속주파수 비트, 48~240Hz Range, CTA 블록)다. 모니터가 "FreeSync Premium Pro 모드 / 일반 모드"에 따라 EDID 테이블을 바꿔 서빙한다는 설명과 일치한다.
- 원격 세션 중에는 절전 상태에서도 데스크톱 합성과 캡처가 계속된다. 이때 드라이버가 FreeSync Premium Pro 모드 진입 신호를 반복하고, 스탠바이 중인 스케일러는 그때마다 모드를 바꾸며 EDID를 교체한다. 그러면 약 42초 주기 루프가 된다. 원격이 없으면 드라이버가 이 신호를 다시 보내지 않으므로 절전 단독으로는 0건이었던 결과와도 맞는다.
- 이 기능을 쓰는 것은 G80SH뿐이다. G50F는 SDR IPS라 해당되지 않으므로 G50F 무증상과도 맞는다.

**수정된 인과 방향**
```
[AMD 드라이버] FreeSync 색상 정확도 ON → 원격 중 절전 상태에서 FS Premium Pro 모드 신호 반복
      ↓
[모니터 스케일러] 모드 전환마다 다른 EDID 테이블(7B0C ↔ 7B0B, 실패 시 Default_Monitor) 서빙
      ↓
[dxgkrnl/PnP] 제품 코드 변화 → 새 노드 → 이전 노드 1010 제거 → 반복
```

모드 전환에 따라 제품 코드까지 바꾸는 것은 여전히 펌웨어 설계 문제다. 다만 **실제로 방아쇠를 당긴 것은 PC 측 드라이버 옵션**이었다.

**확정 방법**: `EDID_Override_Undo.reg` → 재부팅 → 원격+절전 1회. churn이 0건이면 FreeSync 색상 정확도 단독 해결로 확정한다. 반대로 오버라이드는 유지하고 색상 정확도만 다시 켰을 때 루프가 재발하면 방아쇠로 확정한다.

**잃은 것**: GPU 측 FreeSync Premium Pro 톤매핑. VRR(FreeSync) 자체와 Windows HDR은 유지된다. HDR 톤매핑은 모니터/Windows 표준 경로로 처리된다.

## 9. 근원 해결책 검토

### 9-1. EDID_OVERRIDE — 근본 차단 불가

Microsoft 문서로 확인된 적용 순서:

```
1. GPU 미니포트가 물리 EDID 읽음
2. dxgkrnl이 제품 코드로 하드웨어 ID 생성 → PnP 노드 생성   ← 노드는 여기서 확정
3. monitor.sys 로드
4. EDID_OVERRIDE 적용                                       ← 3단계 뒤
```

오버라이드는 노드 생성 **후에** 적용되므로 노드 생성 자체를 막지 못한다. 내용만 바뀐다.

- 근거: [Overriding Monitor EDIDs](https://learn.microsoft.com/en-us/windows-hardware/drivers/display/overriding-monitor-edids), [DxgkDdiQueryDeviceDescriptor](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/dispmprt/nc-dispmprt-dxgkddi_query_device_descriptor)
- Windows 11은 유효한 EDID가 없는 디스플레이에 대해 오버라이드를 무시하므로 `Default_Monitor` 케이스는 대상 외

**부분 효과**: `SAM7B0B` 인스턴스에 `SAM7B0C`의 EDID를 주입하면 Windows가 인식하는 능력치가 같아져 **복귀 시 해상도·창 배치 흐트러짐이 완화**된다. 알림음·유령 노드는 그대로.

레지스트리 구조:
```
HKLM\SYSTEM\CurrentControlSet\Enum\DISPLAY\SAM7B0B\<인스턴스>\Device Parameters\EDID_OVERRIDE
  "0"  REG_BINARY  128바이트 (블록 0)
  "1"  REG_BINARY  128바이트 (CTA 확장 블록)
```

### 9-2. DP 2.1 UHBR로 DSC 우회 — 불가능

| 항목 | 값 |
|---|---|
| 4K 240Hz 10bit RGB 필요 대역폭 | ≈ 68.5 Gbps (블랭킹 0 가정 시에도 59.7) |
| G80SH 지원 | DP 2.1 UHBR20 |
| **RX 9070 XT 지원** | **DP 2.1 UHBR13.5 (유효 ≈ 52.2 Gbps)** |

GPU가 UHBR13.5까지만 지원하므로 어떤 타이밍으로도 비압축 전송이 불가능하다. **DSC는 필수이며 이 경로는 닫힌다.**

### 9-3. Windows 정책 — 존재하지 않음

monitor INF로 제어 가능한 항목은 `MODES`, `MaxResolution`, `DPMS`, `ICMProfile`, `PreferredMode`, `EDID_OVERRIDE`뿐이며 전부 노드 생성 후 적용된다. EDID 변경 시 재열거를 억제하는 정책·레지스트리는 공개 문서상 없다.

관련 완화책으로 **Rapid HPD 완화**(Windows 10 빌드 21287+ 내장, 설정 불가)가 있으나, 이는 "같은 모니터가 잠깐 끊겼다 붙음"을 전제한다. 제품 코드가 바뀌면 다른 모니터로 판정되어 완화가 무력화된다. 창 배치가 깨지는 현상과 정합한다.

### 9-4. AMD 드라이버 EDID 에뮬레이션 — **유일한 소프트웨어 근원 후보**

GPU 드라이버가 물리 EDID 대신 고정 EDID를 dxgkrnl에 전달하면, 모니터가 무엇을 내보내든 Windows는 항상 동일한 EDID를 본다. **위 적용 순서의 1단계에서 개입**하므로 노드 생성 자체를 차단할 수 있다.

- 문서화된 UI는 **Radeon Pro Settings**의 "Display → EDID Emulation"
- ADL SDK에 `ADL2_Adapter_EmulationMode_Set`, `ADL2_Adapter_ConnectionData_Set` API 존재
- **미검증**: 컨슈머 Adrenalin(RX 9070 XT)에서 동작하는지, DSC·UHBR 링크 훈련·VRR·HDR 메타데이터와 함께 온전히 동작하는지
- 위험도: 중~높음 (실패 시 4K240/HDR 손실, 드라이버 재설치로 원복)

### 9-5. 검정 화면보호기 — 패널 케어 사이클 손실

삼성 공식 문서 확인: **Screen Optimization은 모니터가 꺼질 때까지 실행되지 않는다** (누적 4시간 사용 후 자동 활성화, 10~15분 소요, 비활성화 불가).

검정 화면보호기로 링크를 유지하면 발광은 0에 가깝지만 자동 패널 케어 사이클이 돌지 않는다. 장기적으로 물리 off가 유리하다.

## 10. 결론

**근본 원인**: Odyssey G80SH가 모드에 따라 제품 코드가 다른 EDID(`0x7B0B`)를 내보내는 펌웨어 동작. Windows가 이를 별개 장치로 판정하여 노드를 재생성한다.

**방아쇠 (09-16 수정)**: Adrenalin **FreeSync 색상 정확도**. 원격 중 절전 상태에서 드라이버가 FreeSync Premium Pro 모드 전환을 반복시킨 것으로 추정된다. 끈 뒤로 churn 0건이다 (6-5, 4-4).

**조건**: 원격 세션이 개시하고, 화면 절전이 유지한다.

**책임 소재**: 케이블·포트 문제는 아니다. 루프를 개시한 것은 AMD 드라이버 옵션이고, 모드 전환에 제품 코드를 바꾸는 것은 모니터 펌웨어 설계 문제다. **해결**: FreeSync 색상 정확도 끔 (VRR·HDR 유지).

**개체 불량 여부**: 판단 불가. 삼성 Odyssey OLED G8/G9 계열에서 절전-DisplayPort 관련 다중 페이지 스레드가 다수 존재하여 제품군 공통 특성일 가능성이 있으나, 동일 모델(G80SH) 사례는 확인하지 못했다. 커뮤니티는 피해자 편향이 있어 발생률 추정 불가.

### 1순위 — EDID_OVERRIDE 적용 · 잃는 것 없음

`SAM7B0B` 노드에 `SAM7B0C`의 EDID 384바이트(블록 0/1/2)를 주입한다. 비VRR 프로파일로 내려가더라도 Windows가 인식하는 능력치가 동일해진다.

| | |
|---|---|
| 파일 | `개인설정\EDID_Override\EDID_Override_Apply.reg` |
| 적용 | 더블클릭 → UAC 승인 → **재부팅** |
| 되돌리기 | `EDID_Override_Undo.reg` |
| 대상 키 | `HKLM\SYSTEM\CurrentControlSet\Enum\DISPLAY\SAM7B0B\7&16b8ddb4&0&UID256\Device Parameters\EDID_OVERRIDE` |

**해결되는 것**: 절전 복귀 시 해상도·창 배치 흐트러짐

**해결되지 않는 것**: 42초 루프, 알림음, 노드 생성. `Default_Monitor`(EDID 읽기 실패)에는 적용되지 않음 — Windows 11은 유효한 EDID가 없는 디스플레이의 오버라이드를 무시한다. `SAM7B11`이 재등장하면 그쪽에도 별도 적용 필요.

> **주의**: 유령 노드 정리 작업이 `SAM7B0B` 노드를 삭제하면 오버라이드도 함께 사라진다. `GhostMonitorClean` 스크립트는 `EDID_OVERRIDE`가 걸린 노드를 건너뛰도록 수정해 두었다 (rev.2). 반드시 갱신본을 사용할 것.

**7-A. DP 더미 동글 + 원격 중 물리 모니터 분리**

| | |
|---|---|

| 비용 | 약 1만 원 |

**7-B. 삼성 제보**

서비스센터 접수보다 **고객센터 기술문의 또는 커뮤니티 제보**가 유효하다. 재현 조건이 특수(원격 세션 중 절전)하여 센터에서는 재현이 어렵고, EDID 바이트 차이는 본사 엔지니어가 판단할 사안이다.

제보 핵심:

1. 동일 개체(시리얼 `<시리얼>`)가 제품 코드가 다른 EDID(`0x7B0C` / `0x7B0B` / `0x7B11`)를 서빙
2. 384바이트 중 79바이트 상이. 핵심 차이는 feature byte의 연속주파수 비트(0x3B↔0x3A)와 Range 디스크립터(48~240Hz ↔ 30~240Hz)
3. 재현 조건: 4K240 DSC + HDR + FreeSync Premium Pro 활성 상태에서 원격 세션 접속 중 디스플레이 절전 진입
4. 같은 PC의 다른 모니터(G50F)는 동일 조건에서 정상
5. Windows가 제품 코드 변화를 별개 장치로 판정하여 장치 노드를 반복 생성·제거
